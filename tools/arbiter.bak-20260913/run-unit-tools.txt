rem  THE PERMISSION SCOPE FOR AN UNATTENDED UNIT. One rule per line.
rem  Read by run-unit.bat and passed to claude as --allowedTools.
rem
rem  IT IS A DATA FILE ON PURPOSE. Widening the scope must be an edit
rem  here, visible in a diff on its own, rather than a change to the
rem  launcher's logic. A guard that is widened in the same commit as
rem  the code that needed widening is a guard nobody can review.
rem
rem  rem lines and blank lines are ignored.
rem
rem  ---------------------------------------------------------------
rem  TWO FLAGS, TWO JOBS, and confusing them is the trap.
rem
rem    --tools        names which BUILT-IN tools exist at all.
rem                   claude --help: --restricted "removes the
rem                   built-in tools that run commands or code (Bash,
rem                   PowerShell, REPL and the other code-running
rem                   tools) and WebFetch UNLESS --tools NAMES THEM".
rem    --allowedTools is the permission scope over those tools -
rem                   these lines.
rem
rem  A tool absent from --tools has nothing to deny, so
rem  permission_denials stays EMPTY while the work silently does not
rem  happen. run-unit.bat therefore prints both lists on every run.
rem  The --tools list lives in the launcher because it is the shape
rem  of the session rather than its scope; this file is the scope.
rem  ---------------------------------------------------------------
rem
rem  Permission rules match the WHOLE command string, so a compound
rem  command is refused even when its parts are allowed. That refusal
rem  is loud - it arrives in permission_denials naming the exact
rem  string - and widening this file is then an edit informed by
rem  evidence rather than by guessing. The owner accepted that cost
rem  in the 2026-08-28 ruling.
rem
