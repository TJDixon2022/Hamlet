WHY IT IS WRITTEN OUT HERE RATHER THAN LEFT TO THE READER. Unit 323 read this
file as a list of names and ran one `dotnet test` per name - forty-one builds.
It wrote one status line at 17:43, started the run, and the watchdog killed it
at 17:55 for twelve minutes of silence. It had done nothing wrong except obey
the shape of this file. **Two invocations. One build each. Status written
immediately before each one** (HM-DEC-155, and work instruction 324 section 1).

A short type name is enough inside one project, because a filter is scoped to
the assembly it is run against: `ThePsk31OfferTests` exists in both projects and
each line above matches only its own. Where a single method is wanted rather
than a whole type, the type-and-method form is used, as `BindingHealthTests`
does.

WHAT THIS IS. The test names a unit runs, filtered and foregrounded, BEFORE it
changes anything - so that a red found afterwards can be told from a red that
was already there. HM-DEC-155 forbids running a suite, and this list is what a
unit runs instead.

WHAT IS NEVER ON IT. A known red. The point of the list is that everything on it
should be green before a unit starts; a name that is expected to fail teaches the
next session to ignore a failure.

WHAT IS NOT ON IT ANY MORE. Twenty-four names, dropped by unit 324 under work
instruction 324 task 1b and **written down, with the unit that added each one,
in `docs/carry-forward-dropped.txt`**. Nothing is lost; it is only not re-run.
A list that only ever grows becomes a suite, and a suite is what HM-DEC-155
forbids and what the watchdog kills.
