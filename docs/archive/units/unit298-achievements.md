### What a record actually holds

`AdifContact` (`src/Hamlet.RadioEngine/Contacts/AdifLog.cs:19-70`) is thirteen
nullable fields, and **null means not observed** rather than empty:

| Field | ADIF | Written at | Read back at |
|---|---|---|---|
| `Call` | `CALL` | `AdifLog.cs:251` | `:476` |
| `StationCallsign` | `STATION_CALLSIGN` | `:252` | `:477` |
| `StartedUtc` | `QSO_DATE` + `TIME_ON` | `:256-257` | `:478` |
| `EndedUtc` | `QSO_DATE` + `TIME_OFF` | `:268-271` | `:479` |
| `Band` | `BAND` | `:274` | `:480` |
| `FrequencyMhz` | `FREQ` | `:289` | `:482` |
| `Mode` | `MODE` | `:275` | `:481` |
| `Submode` | `SUBMODE` | `:282` | `:482` |
| `ReportSent` | `RST_SENT` | `:292` | `:488` |
| `ReportReceived` | `RST_RCVD` | `:293` | `:489` |
| `GridSquare` | `GRIDSQUARE` | `:294` | `:490` |
| `MyGridSquare` | `MY_GRIDSQUARE` | `:295` | `:491` |
| `Comment` | `COMMENT` | `:296` | `:492` |

**The reports are signed integers in a fixed shape**, `+00;-00`
(`Ft8ContactLogEntry.cs:181-182`), so a record carries `-09` or `+02` and never `59`.
That matters: they parse, and they are decibels rather than an RST.

for an imported file it may not be. A record with no `GRIDSQUARE` cannot contribute
to a distance or a grid count and must not be counted as a zero.

### The two that cannot be computed, and why

**Continents.** `data/callsigns/dxcc-prefixes.json` holds `source`, `prefixes` and
`sharedAndThereforeSilent`, and nothing else - **the string `continent` does not
occur anywhere in the file.** 605 prefixes resolve to **275 distinct entities**. The
transcription it is generated from, `tools/dxcc/arrl-dxcc-current.txt`, is 306 lines
of `PREFIX = Entity name`: two columns, no third.
`data/callsigns/entity-extents.json` carries only a north and a south latitude, for
**ten** entities, and a latitude cannot name a continent - the same parallel runs
through Africa, Asia and America.

**What it would take.** The table is generated by `tools/dxcc/expand-prefixes.py`
from the transcription, and that script's own header records why: *work instruction
252 task 3 forbids typing a prefix table from memory and requires the table to come
from a published allocation, cited.* **The same rule binds a continent column.** So
it takes a return to the cited publication - the ARRL DXCC List at the URL the source
note names - to see whether it carries a continent beside the prefix and the entity;
if it does, that is one more column through the same expander and nothing is
invented. **If it does not, it needs a second cited source**, and this tree cannot
say today which of those two it is.

**What it must not take, and this is the finding rather than the caveat: 275
entity-to-continent pairs written from a model's memory.** That is exactly what §0
forbids and what unit 252 built this machinery to prevent, and it would be
undetectable afterwards - a continent card is not a figure anybody checks.

**US states.** The same shape and it is unit 297's finding again.
`DxccPrefixes.EntityOf` names a DXCC entity, which for the whole of the fifty states
is *United States of America*, and `EntityQualifier` adds only *northern* or
*southern*. **A US call area is historical and not a residence** - an operator keeps
his callsign when he moves, so `W6` in Ohio is ordinary - and a four-character grid
square is a box about seventy miles across that straddles state lines. Neither route
is honest and there is no cited grid-to-state table here.

### Named and left, per the instruction

**Transmit power: absent, and absent by a decision rather than an oversight.** There
is no field for it on `AdifContact` at all. ADIF has `TX_PWR`; Hamlet does not write
it, and **it could not fill it honestly if it did**: HM-DEC-074 and HM-DEC-082 have
Hamlet report power as a percentage of the radio's own range and never as a wattage,
and §13.4 records that the transmitter's power output is the one rating `CLAUDE.md`
does not carry. So there is no wattage anywhere in this application to put in a log.

**Contact duration: the instruction's guess is wrong and it is derivable.**
`EndedUtc` is written as `TIME_OFF` (`AdifLog.cs:268-271`) and read back
(`:479`), and `Ft8ContactLogEntry.For` sets it from the ledger's own moments -
`StartedUtc` the first and `EndedUtc` the last message either way. **What it measures
is the span of the exchange**, first message to last, which for FT8 is about a minute;
it is not how long the transmitter was keyed and a card must not word it that way.

`TIME_OFF` is written **only where `QSO_DATE` is** (`:268`), and the remark beside it
says why: an end time with no date belongs to no day, and a reader would have to
invent one.
