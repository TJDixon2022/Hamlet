# Traceability - every CW test and every CW requirement

Work instruction 439, tasks 1 and 2 (PHASE_PLAN.md criteria 0.1, 0.2 and 0.3), run by hand
outside the loop on 2026-09-25. The specification is `CW_REQUIREMENTS.md` and `CW_SPEC.md` at
the repository root (HM-DEC-183, R77); nothing here changes either, and nothing under `src` or
any test file was changed to write it.

## How a test was judged

A test **proves** a requirement when what it asserts is what the requirement states: the same
behaviour, under the requirement's condition or a narrower instance its verification row
accepts, against the requirement's threshold or a stricter one. A test that asserts a
mechanism the requirement does not name, or prints and asserts nothing, proves `none`. A test
on a requirement's subject that measures something else - another threshold, a character-count
floor, part of the required range, a ratchet where the row says pass or fail, another
condition - proves `none` and names that requirement under **measures something else**, with
the reason. Where the answer is genuinely unclear the column says `unclear` and why. Nothing
was assigned to fill a column (`CLAUDE.md` 0.0). The rubric is `.run-unit/unit439h-rubric.md`;
the classification was read from each test's source, and every proving row below was re-read
by the session before it was accepted.

Everything the specification puts outside the receive decoder (`CW_SPEC.md` section 2) - the
transmit path, the keying sweep, the capture and sidecar writer, the terminal, the scanner, the
contact-state model and callsign claiming - proves `none` here by construction, and its note
says so.
