feat(unit293): task 4 - the log says the mode it was actually made in

One line, and it is the only thing in this unit that could be wrong for as long
as the log exists. MainWindowViewModel's one write path handed in
ContactModes.Named("FT8") unconditionally. It was unreachable on FT4 only
because CanLogRow needs a station to have addressed the operator, and nothing
could address him on FT4 until Hamlet could transmit on it - which tasks 2 and 3
made possible, so it changes in the same unit.

The mode is now DigitalMode.Contact(), a lookup on the same one value the grid,
the cutter, the slot watch and the decoder already derive from. Not a second
source, not a string, and not the chip's lit state, which is a reading of where
the dial is rather than an instruction about what Hamlet is doing. The mapping
onto MODE=MFSK plus SUBMODE=FT4 is unit 291's table and is not re-derived.

The record construction is lifted out of LogContactAsync into
ContactLogEntryFor, which writes nothing and opens nothing, so what goes into
the permanent record can be asserted without a dialog.

Both directions are asserted. FT4: MODE=MFSK, SUBMODE=FT4, and the string FT8
appears nowhere in the record. FT8: MODE=FT8 with SUBMODE absent rather than
empty, exactly as unit 291 pinned it. The same seeded row logged under each mode
in turn gives each answer, so the mode follows the tab and nothing else.

The achievements FT4 row lights off a record this write path made rather than
off a forced one - the first unit in which a real FT4 contact is reachable.
