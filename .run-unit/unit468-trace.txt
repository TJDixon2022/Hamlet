== What the tree can already vary

CwFixtureRecipe (tests/Hamlet.RadioEngine.Tests/Cw/Fixtures/CwFixtureGenerator.cs 38-57), keyed by CwFixtureGenerator.KeyEdges (365-465):
  DitMilliseconds          - varies: any dit length.
  DahMilliseconds          - varies: separate from the dit, so any dah-to-dit ratio (the default 283 against 105 is 2.70).
  ElementGapMilliseconds   - varies: any element gap, including shorter than the dit (default 65).
  CharacterGapMilliseconds - varies: any character gap (default 130).
  WordGapMilliseconds      - varies: any word gap (default 280).
  character speed vs overall speed - NOT a parameter. It follows from the five lengths: stretch the character and word gaps with the dit fixed and the overall rate falls below the character rate. So Farnsworth is expressible with no new field.
  per-element jitter       - NOT variable. Every dit is DitMilliseconds, every gap of a class is the same length. KeyEdges has no random draw; the seed feeds only the noise.
  Also present, not timing: ToneHz, DriftHz, DriftHzPerSecond, QsbHz/QsbDepthDb, PreambleSeconds, SignalToNoiseDb (in-passband), Seed (noise).
  The defaults are 013347's fist as fitted under HM-DEC-101 (KeyEdges' remarks: element gaps about 65 ms against dits of 105, character gaps 130).

SyntheticCq.Recipe(wpm, snrDb, seed, characterGapUnits = 3) (SyntheticCq.cs 71-87):
  dit = 1200 / wpm; dah 3; element gap 1; character gap = characterGapUnits (3, or 5 for the wide row); word gap 7. Nothing else is exposed.
  So SyntheticCq keys TX-ITU and one character-gap-5 variant only.

CwChannel.Generate / Render (CwChannel.cs 127-222):
  Takes a message and a wpm, and builds its own keying: SyntheticCq.Recipe(wpm, 0, seed) with Text = key, ToneHz = pitch, DriftHz = 0. That is TX-ITU hard-wired: the channel cannot take any other sender's keying today.

== Which section 10 profile each parameter serves

  TX-ITU      - dit, dah = 3, element 1, character 3, word 7: all present (SyntheticCq.Recipe).
  TX-KEYER-W  - dah (ratio 2.5-3.5) and the three gaps (+-30 %): all expressible through the recipe's five lengths; no draw exists.
  TX-FARNS    - character gap (3-7 units at character speed) and word gap (longer): expressible through the recipe; character vs overall speed follows from them. Not reachable through CwChannel.
  TX-TIGHT    - element gap below the dit, compressed character gap: expressible; the recipe's own defaults are the 013347 fist. Not reachable through CwChannel.
  TX-BUG      - dah (ratio 3.5-5): expressible. "Dits short and fast, gaps variable" carry no number.
  TX-STRAIGHT - "ratio and gaps drift; speed wanders": needs per-element variation, which the tree cannot produce, and section 10 gives no number for it.
  TX-SLOPPY   - "inconsistent ratios, missing gaps, errors and corrections": no number, and errors change the characters sent.

== What is missing

  1. A sender layer: profile id + text + speed + seed -> the five lengths, with any drawn parameter drawn from the seed and written down. No such thing exists (section T row 050-053: "none: needs TX-* profiles in generator").
  2. A way into CwChannel for a keying other than TX-ITU: Render builds the recipe itself. An overload that takes the recipe (or the edges) is needed; the existing signature must render byte-identically so unit 461's 71 cases stay as they are.
  3. A proof of the rendered keying per profile. RenderedKeying.Measure exists (SyntheticCq.cs 315) but the instruction asks for measuring code written for the new test; it will not be reused.
  4. Per-element jitter: absent. None of the four must-tier definitions, nor TX-BUG's, gives a jitter number, so it is not needed for any profile produced here; its absence is one of the reasons TX-STRAIGHT cannot be produced.

== How CwChannel takes a keyed envelope and sets the SNR in the 2500 Hz reference

  Edges: CwFixtureGenerator.KeyEdges(recipe) -> key-change instants in seconds, 1.0 s lead-in.
  Envelope: CwChannel.Envelope(edges, count): the generator's Gate, a 5 ms raised cosine inside each element, 0 between.
  Paths: CH-AWGN is one path, h1 = 1 (Fades is false), so path1 = envelope and path2 = 0.
  Band: CwFixtureGenerator.ShapedNoise(noise, seed) - 350-870 Hz, three biquads, skirt 30 dB down - times NoiseScale 0.5 (rms 0.01). Never digital silence (V-06). Added after the signal, never faded.
  SNR: n0 = BandDensity(pitch) * 0.5^2, the band's one-sided density at the tone from the biquads' own response; tone power P = 10^(snr/10) * n0 * 2500; amplitude = sqrt(2 P). So the stated SNR is tone power over the noise density at the tone times 2500 Hz (CW_SPEC 8.1).
  Output: signal = amplitude * Re{(path1 + path2) e^(j w n)}, audio = clamp(noise + signal). Render returns the pieces (Signal before noise, Noise, Edges) in CwChannelParts, so a proof can measure the tone before the band is added.
