== 1. What the tree can already mix

a. A second keyed tone: CwFixtureGenerator.Together(wanted, other, levelDb)
   (tests/.../Cw/Fixtures/CwFixtureGenerator.cs:255). Renders the generator's
   ShapedNoise once, then both recipes' keying on top (RenderKeying). The other
   station's pitch is its recipe's ToneHz, so the offset is ToneHz - wanted.ToneHz;
   its level is levelDb against the wanted; its speed is its own recipe's lengths.
   Start time: only through the recipe's PreambleSeconds, which is not a delay - it
   renders own-transmit mutes (CwFixtureGenerator.cs:340, 669-677). CwTwoInOnePassband
   (unit ~420s) uses it at PreambleSeconds 0.35 with "DE N0AAA UP" at 24 WPM over
   "CQ DE N0CALL K" at 18 WPM, 600 Hz, 15 dB, offsets 40-300 Hz, levels 0/-6/-12.
   TheTwoStationTable sweeps it and writes ANALYSIS-cw-two-stations-2026-08-23.md.
b. A steady tone: nothing in the fixtures folder. Unit 448's carrier case is built
   by hand in ThePitchInstrumentIsProvedTests.Cases() (Cw/ThePitchInstrumentIsProvedTests.cs:102-117):
   Generate() a 625 Hz keyed CQ, read the band RMS from the 0.9 s lead-in, and add
   sqrt(2) bandRms 10^((15+6)/20) sin(2 pi 525 n / fs) to every sample - present
   from sample 0, never keyed, level stated against the keyed tone's amplitude.
c. Offset, level, start time: Together takes offset and level; start only by the
   preamble side effect. The carrier case takes offset and level, start = sample 0.

== 2. Where the level is set, and whether it is relative to key-down power

- Together: wantedAmplitude = sqrt(2) noiseRms 10^(snr/20); otherAmplitude =
  wantedAmplitude 10^(levelDb/20). Both are key-down peak amplitudes, so levelDb IS
  relative to the wanted's key-down power (a ratio of keyed amplitudes, not of
  averages - TheTwoStationTable says so in its own page). The SNR, though, is the
  generator's "over the band" figure (tone peak over band RMS), NOT CW_SPEC 8.1's
  2500 Hz reference.
- The 448 carrier: relative to the keyed tone's peak amplitude, i.e. key-down power.

== 3. How a mix passes through CwChannel's CH-AWGN, and where the SNR is set

- CwChannel.RenderKeyed(profile, snrDb, recipe, pitchHz, seed, sender) renders ONE
  keyed recipe: ShapedNoise x NoiseScale 0.5 (rms 0.01, -40 dBFS), n0 =
  BandDensity(pitch) x 0.25, power = 10^(snr/10) n0 2500, amplitude = sqrt(2 power),
  signal = amplitude x envelope x cos(2 pi f t), audio = clamp(noise + signal).
  The SNR in the 2500 Hz reference is therefore set on that one station at its own
  pitch. There is no second layer: CwChannel cannot mix anything today.
- CwChannelParts returns Signal (the tone, before the band) and Noise (the band as
  added) separately, so a second layer can be summed between them and the SNR
  still be set on the wanted station alone. Envelope() is private; KeyEdges and
  Gate are internal on CwFixtureGenerator and reachable from the fixtures.
- CwSender.Keyed/Render (unit 468) drives RenderKeyed with a TX-* recipe at
  CwSender.PitchHz 600; TX-ITU is 1:3:1:3:7 with no draws.

== 4. What the decoder reports as tracked pitch, and where "competing" is decided

- Tracked pitch: CwDecoder.Report.ToneHz = CwToneTracker.ToneHz (src/.../Cw/CwDecoder.cs:456,
  CwToneTracker.cs:443), readable after every hop through decoder.Tracker.ToneHz.
  The fixtures' Settle loop (TheMustFistsAtFifteenDecibelsFact) drives CwDecoder hop by
  hop from 600 Hz, so the pitch can be read at any sample.
- Competing: decided in the ENGINE, CwToneTracker.Competitor (CwToneTracker.cs:597-633),
  surfaced as CwDecodeReport.Competitor (CwDecoder.cs:468; CwDecodeReport.cs:69) - a
  CwCompetitor(OffsetHz, RelativeDb, ToneHz). It walks CwToneSurvey.Candidates() and
  keeps the loudest candidate with |offset| >= CwCompetitor.SeparationHz (125 Hz) and
  relative >= QuietestWorthSayingDb (-20 dB); null while nothing keyed is being read.
- The app composes the sentence: MainWindowViewModel.CompetitorForTheRecord
  (MainWindowViewModel.cs:12566) writes "competing  <|offset|> Hz <above|below> at
  <rel> dB relative (<tone> Hz)" when Competitor is set, else "none admitted, and the
  survey is not silent: ..." (Interference set) or "none found, and the survey found
  nothing else either - which is not the same as the frequency being clear" (12601).
  The on-screen sentence is CwCompetitor.Sentence.
- CONSEQUENCE FOR HM-REQ-066 AS THE INSTRUCTION FRAMES IT: the case is a second keyed
  station at +100 Hz. The engine never names a candidate nearer than 125 Hz
  (CwCompetitor.cs:59 "Two operators closer together than this are not named"), so by
  construction the tree cannot report the 066 cases' second station. Measured, not
  assumed: task 2 prints what the report holds at every hop.

== 5. The detector bandwidth in force (INT-COCHAN is defined against it)

CwProbabilisticDecoder.IntegratorBandwidthHz = 45.0 Hz, IntegratorName "Hann"
(CwProbabilisticDecoder.cs:416, 425): the integrator's equivalent noise bandwidth,
centred on the tracked tone, so a second tone within +-22.5 Hz lies inside it.

== 6. What is missing

  the wanted station BEFORE CwChannel's band, with the 2500 Hz reference SNR set on the
  wanted alone - Together uses the generator's own "over the band" SNR, and nothing
  mixes over CH-AWGN.
- A start time for an interferer that is a delay and not own-transmit mutes.
- A sidecar carrying each interferer's pitch, level, speed, text, start and seed.
- A proof that measures an interferer's offset, level and keyed-or-steady from the
  rendered audio (TheTwoStationTable's Overlap measures collisions through the
  decoder's own front end, which CLAUDE.md 12.5 bars as the proof here).

  33.98 + 15 = -16.1 dBFS of power, a peak near 0.22 FS (n0 read from the entry
  round's channel sidecar); a carrier 20 dB above it peaks near 2.2 FS and would clip.
  Nothing in the tree scales a case.
- Any report of a competitor nearer than 125 Hz (HM-REQ-066's rows), and any
  decode-side INT-* measurement: section T row 060-062, 066 reads "none".
