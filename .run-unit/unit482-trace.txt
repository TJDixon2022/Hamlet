2. THE GATE AND WHAT OPENS IT

  The gate is the button's IsEnabled="{Binding IsDecoding}" (MainWindow.axaml:1795 and 1801) - unit 478's claim holds.
  IsDecoding (MainWindowViewModel.cs:1073) is set true in exactly one place, StartDecoding (11362), after an audio
  input opens (11265); it goes false when none opens (11275) and when decoding stops (11471).
  At runtime and headless it opens by Connect:
    ToggleConnectCommand -> ConnectToAsync(port) (13700) -> StartDecoding() (13765) -> OpenAudioInput() (11379)
    -> with the training radio (_rig.IsSimulated) a TrainingAudioSource (11388-11396), no device opened -> IsDecoding = true (11362).
  Headless, the path the tree already uses is TheControlsTimCanPress.ConnectAsync
  (tests/Hamlet.App.Tests/Views/WhatEveryControlSaysOnHoverTests.cs): SelectedPort = TrainingRadio, ToggleConnectCommand.
  Connecting attaches the transmitter door (13770) but nothing keys; no press here reaches it.

  Note: the gate lives on the button only. AgreeCommand/IdiotCommand have no CanExecute, so a call on the view model
  writes a row with the gate shut. That is why the test goes through the button (its Command and its IsEnabled).
